# AllScaner - инструкция по запуску и проверке

Приложение помогает людям с пищевой аллергией проверять состав продуктов.
Состав можно получить двумя способами: сфотографировать этикетку (OCR) или
отсканировать штрихкод / QR-код (Open Food Facts). Проверку выполняет
Python-сервер на FastAPI.

> AllScaner - информационный помощник, а не медицинское устройство.
> Результат не гарантирует безопасность продукта.

## Структура

```
AllScaner/
├── app/                         Android-приложение (Kotlin, Jetpack Compose)
│   └── src/main/java/com/example/allscaner/
│       ├── MainActivity.kt      все экраны и навигация
│       ├── ServerApi.kt         Retrofit: Python-сервер, Open Food Facts, обработка ошибок
│       ├── TextRecognizer.kt    OCR (Tesseract, rus+eng), поворот фото
│       ├── AppDatabase.kt       Room: база данных + класс приложения
│       ├── Allergen*.kt, ScanRecord*.kt   таблицы и запросы Room
│       └── ui/theme/            тема (без изменений)
├── server/                      Python-сервер
│   ├── main.py                  FastAPI: адреса /health и /check, модели Pydantic
│   ├── checker.py               умная проверка (алгоритм)
│   ├── allergen_dictionary.py   словарь аллергенов (RU + EN)
│   ├── test_checker.py          48 автотестов
│   └── requirements.txt
└── README.md, ЗАЩИТА.md
```

## 1. Запуск Python-сервера (Windows)

Нужен Python 3.10 или новее. В PowerShell:

```powershell
cd server
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

Проверка: откройте в браузере http://localhost:8000/docs. Там можно отправить
тестовый запрос на `/check` прямо из браузера.

`--host 0.0.0.0` нужен, чтобы к серверу мог подключиться телефон.
Если Windows спросит про брандмауэр, разрешите доступ для частной сети.

## 2. Запуск Android-приложения

1. Откройте папку проекта в Android Studio, дождитесь синхронизации Gradle.
   (Файл `local.properties` Android Studio создаст сам. Свой старый тоже можно оставить.)
2. Запустите приложение на эмуляторе или телефоне.
3. Адрес сервера:
   - **Эмулятор:** ничего менять не нужно, по умолчанию `http://10.0.2.2:8000/`
     (10.0.2.2 - это ваш компьютер с точки зрения эмулятора).
   - **Настоящий телефон:** телефон и компьютер должны быть в одной Wi-Fi сети.
     Узнайте IP компьютера командой `ipconfig` (строка «IPv4-адрес», например 192.168.1.5).
     В приложении: **Настройки -> Адрес сервера проверки** -> `http://192.168.1.5:8000/` ->
     «Сохранить и проверить соединение». Должно появиться «Сервер доступен».

## 3. Проверка по шагам (чек-лист)

| № | Что сделать | Ожидаемый результат |
|---|---|---|
| 1 | Запустить сервер, открыть `/docs` | Страница документации |
| 2 | Настройки -> проверить соединение | «Сервер доступен.» |
| 3 | Мои аллергены -> добавить «молоко», «арахис», закрыть и открыть приложение | Аллергены на месте |
| 4 | Сканировать -> Штрихкод / QR -> показать штрихкод продукта (например, шоколадки) | Название продукта, состав, статус |
| 5 | Сканировать -> Этикетка -> «Снимок» на состав на упаковке | Распознанный состав и статус |
| 6 | Остановить сервер, повторить проверку | Понятное сообщение об ошибке и кнопка «Повторить проверку» |
| 7 | Удалить все аллергены, отсканировать | «Список аллергенов пуст...» |
| 8 | Запретить камеру в настройках телефона | Сообщение и кнопка «Открыть настройки приложения» |
| 9 | Отсканировать QR со ссылкой | Показано название сайта, ссылка НЕ открывается |
| 10 | История -> открыть запись | Подробности с объяснениями совпадений |

Тесты Python-части: `cd server`, затем `python -m pytest -v` (должно пройти 48 тестов).

## 4. Статусы результата

- **Обнаружен аллерген** - найдено прямое совпадение.
- **Возможное совпадение** - найден производный или связанный ингредиент, упоминание
  «может содержать следы», слово с возможной ошибкой распознавания или пометка «без ...».
- **Совпадений не найдено в проверенном составе** - ничего не найдено. Это НЕ значит «безопасно».
- **Недостаточно информации для проверки** - пустой состав или пустой список аллергенов.

## 5. Что изменилось в проекте (и почему)

- `AllergenChecker.kt` удалён: проверка теперь в Python (`server/checker.py`), по ТЗ.
- В `ScanRecord` добавлены поля `productName`, `status`, `resultJson`; версия БД 2 -> 3.
  При обновлении старая история очищается (`fallbackToDestructiveMigration`).
- База Room создаётся один раз в классе `AllScanerApp`, а не внутри экрана.
- Экран зафиксирован в портретной ориентации: CameraX считает поворот фото относительно неё.
- В манифесте: `INTERNET`, `usesCleartextTraffic` (сервер работает по http в локальной сети),
  `allowBackup=false` (данные об аллергии не уходят в облачный бэкап).
- В Gradle добавлены: ML Kit Barcode Scanning, Retrofit, Gson-конвертер, OkHttp.
- Добавлен `eng.traineddata`: английский текст на этикетках.
- Версии Gradle, AGP, Kotlin, Compose, Room не менялись.

## 6. Известные ограничения

- Open Food Facts может не знать продукт или не содержать его состав. Тогда приложение
  предлагает сфотографировать этикетку.
- Качество OCR зависит от освещения, шрифта и изгибов упаковки.
- Словарь аллергенов охватывает 15 групп (основные аллергены ЕС, мёд, цитрусовые).
  Для остальных слов поиск идёт по слову, которое ввёл пользователь, без производных.
- Сервер должен быть запущен на компьютере. Без него проверка не работает
  (приложение покажет понятную ошибку).

## 7. Сервер в интернете (чтобы пользователь ничего не вводил)

Идея: Python-сервер работает на бесплатном хостинге Render.com, а его адрес вписан в приложение.
Тогда пользователь просто ставит приложение и пользуется им.

1. **GitHub.** Создайте аккаунт на github.com и новый репозиторий (Private или Public).
   Загрузите в него весь проект (кнопка «Add file -> Upload files» или Git).
   Важно: в корне репозитория должен лежать файл `render.yaml` и папка `server`.
2. **Render.** Зарегистрируйтесь на render.com через GitHub.
   Нажмите **New -> Blueprint**, выберите ваш репозиторий и подтвердите.
   Render прочитает `render.yaml` и сам установит и запустит сервер (3-5 минут).
3. Когда сервис станет «Live», скопируйте его адрес вида `https://allscaner-api.onrender.com`.
   Проверьте: откройте `https://ваш-адрес/docs` в браузере.
4. В файле `app/src/main/java/com/example/allscaner/ServerApi.kt` замените значение
   `DEFAULT_SERVER` на свой адрес (с `/` в конце), пересоберите приложение и установите его.

Особенности бесплатного тарифа: если сервером 15 минут не пользовались, он «засыпает» и
следующий запрос идёт до минуты. Поэтому перед защитой откройте `https://ваш-адрес/health`
за пару минут до показа, чтобы «разбудить» сервер.

В отладочной сборке (из Android Studio) в «Настройках» остаётся поле адреса,
чтобы разработчик мог временно указать локальный сервер. В обычной сборке его нет.
